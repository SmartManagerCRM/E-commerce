# SmartManager Storefront Design System

The storefront design system is organised in layers: tokens feed the theme, and tenants customise on top of the theme. Components never hard-code colours, fonts, radii or spacing.

```
design tokens (CSS variables)  ←  theme definition  ←  tenant overrides (validated)
        ↓
Tailwind semantic utilities (bg-surface, text-muted, rounded-button, font-display …)
        ↓
primitives → commerce components → homepage sections → pages
```

## 1. Tokens

| Group | Tokens | Source |
|---|---|---|
| Colour | `bg`, `surface`, `fg`, `muted`, `border`, `primary`, `primary-fg`, `accent`, `accent-fg`, `accent-text`, `primary-text`, `danger`, `success`, `warning` | `src/themes/tokens.ts` → `--sm-color-*` |
| Type | `font-display`, `font-sans`, `text-display-xl/lg/md` (fluid) | theme + tenant typography |
| Shape | `rounded-sm/md/lg`, `rounded-button` | theme + tenant button style |
| Elevation | `shadow-card`, `shadow-overlay` | `globals.css` |
| Motion | `ease-standard`, durations 150–500 ms, disabled under `prefers-reduced-motion` | `globals.css` |
| Spacing | Tailwind's 4 px scale; section rhythm `py-16 sm:py-24`, page gutters via `<Container>` | components |

**Contrast rules:**
- `*-fg` tokens are computed to be readable on their background.
- Use `*-text` tokens whenever a brand colour is used for text or icons. They are automatically darkened to at least WCAG AA contrast (4.5:1), so tenants can pick any brand colour.

**RTL:** use logical utilities only (`ms/me`, `ps/pe`, `start/end`, `text-start/end`). Mirror directional icons with `rtl:-scale-x-100`. Arabic headings use `rtl:leading-*` overrides for diacritics.

## 2. Themes

Defined in `src/themes/definitions.ts`:

| Theme | Display type | Buttons | Product cards | Header |
|---|---|---|---|---|
| Premium Café | Modern serif (Fraunces) | Rounded | Minimal | Classic |
| Modern Restaurant | Sans | Pill | Elevated | Classic |
| Modern Retail | Sans | Square | Bordered | Classic |
| Luxury | Classic serif (Cormorant) | Square | Minimal | Centred |
| Beauty | Classic serif | Pill | Minimal | Centred |

To add a theme, add an entry to `THEMES`; no component changes are needed.

**Tenant customisation** (Appearance page, validated by `src/lib/storefront/design.ts`): colours, typography, button style, product-card style, header layout, sticky header, announcement bar, social links, logo, favicon.

## 3. Components

| Layer | Components |
|---|---|
| Primitives (`components/ui`) | Button, Badge, Container, SectionCard, EmptyState, Skeleton, Drawer (focus-trapped side sheet, direction-aware), Toast (live region), Field / Select / TextArea / LocalizedFields |
| Commerce (`components/store`) | Price (sale + screen-reader text), Rating, QuantityStepper (44 px targets), VariantSelector (native radio group), ProductCard (3 styles, single tab stop), ProductGrid, ProductGallery (thumbnails + swipe), MediaImage (fixed ratio, AVIF/WebP, no layout shift), SectionHeading, SmartLink |
| Layout | StoreHeader (classic / centred, announcement, sticky), MobileMenu, StoreFooter (contact, social), StoreUnavailable |
| Sections (`components/store/sections`) | Hero (split / centred / full-image), Promo banner, Brand story, Testimonials, Location & hours, Newsletter |

**Design preview:** Appearance → *Design preview* renders every catalog component in the tenant's current design, using clearly labelled sample content (artwork generated by `scripts/generate-preview-art.mjs`).

## 4. Homepage sections

- Stored as a validated JSON array (`storefront_configs.homepage_sections`), parsed by `src/lib/storefront/sections.ts`.
- Malformed entries are dropped, and unsafe links (`javascript:`, protocol-relative `//`, `http:`) are rejected on save.
- Until a tenant saves, the homepage is generated only from its real profile (name, tagline, description, address); nothing is invented.
- Sections that need modules not built yet (featured products, categories, best sellers, collections, loyalty, booking) are listed with the phase in which they become available. They cannot be enabled before then.

## 5. States

Every surface has loading, empty, error and success states: skeletons, `EmptyState`, route-level `error.tsx` / `not-found.tsx`, and form results announced via `role="status"` / `role="alert"`. Forms keep the user's input after a server-side validation error (`useActionForm`).
